# 因子分析模块

## 概述

因子分析模块用于评估小市值策略的真实表现和超额收益来源，通过四个核心维度（Rank IC、分组收益、因子暴露、行业中性 Alpha）提供深度的策略分析。

### 核心指标

| 指标 | 说明 | 解读 |
|------|------|------|
| **Rank IC** | 市值因子与收益的秩相关系数 | IC > 0.1 表示因子有预测能力 |
| **五分组收益** | 按市值分组后的收益对比 | 第1组收益 > 第5组表示小市值溢价 |
| **因子暴露** | 策略 vs 基准的行业/市值/流动性差异 | 定量化策略的特征暴露 |
| **行业中性 Alpha** | 剔除行业效应后的选股能力 | Alpha > 0 表示真实的选股超额收益 |

## 1. Rank IC 时间序列

### 计算方法

每个月末调仓日期，计算市值因子与后续持股期间收益的秩相关：

```
步骤1: 在信号日期(月末)获取候选股票的市值排序
步骤2: 计算这些股票在后续持股期间的日收益
步骤3: 对市值排名 vs 收益做秩相关(Spearman)
步骤4: 输出IC值、p-value和样本数
```

**关键特征：**
- **时间对齐**：市值在信号日期获取，收益在后续期间计算（防止数据穿越）
- **秩相关**：使用 Spearman 秩相关而非Pearson，对异常值更稳健
- **日级别**：计算每个交易日的收益，捕捉高频的选股能力

### 解读指南

**IC 值**
- IC ∈ [-1, 1]，1 表示完美正相关，-1 表示完美负相关
- IC = 0 表示无相关性（因子无预测能力）
- 小市值策略通常 IC < 0 或 IC 接近 0（因为小市值是反向择股）

**P-Value**
- p-value < 0.05：统计显著（95% 置信度）
- p-value < 0.1：弱显著（90% 置信度）
- p-value > 0.1：不显著

**T-Stat（自动计算）**
- t-stat = 平均IC / IC的标准差
- t-stat > 2：表示 IC 序列显著非零
- t-stat > 1：表示有一定统计支持

### 例子

假设回测跨越 12 个月，每月末生成一个 IC：

```
2024-01-31: IC=0.15, p-value=0.08, sample_size=28
2024-02-29: IC=0.22, p-value=0.03, sample_size=29
2024-03-31: IC=0.08, p-value=0.42, sample_size=27
...
2024-12-31: IC=-0.05, p-value=0.61, sample_size=26

平均IC:     0.10
IC标准差:   0.12
IC T-Stat:  0.83 (= 0.10 / 0.12)
```

**解读：** 平均 IC 为正（0.10），但 T-Stat < 2，说明统计显著性不强。该因子有选股能力但不稳定。

## 2. 五分组收益分析

### 分组方法

按市值升序排列所有候选股票，平均分成 5 组，每组等权重：

```
候选30只股票 → 按市值升序排列
第1组（最小市值）: 股票1-6
第2组: 股票7-12
第3组: 股票13-18
第4组: 股票19-24
第5组（最大市值）: 股票25-30
```

### 关键指标

| 指标 | 定义 | 说明 |
|------|------|------|
| **平均收益** | 该组股票的日均收益 | 越高越好 |
| **累计收益** | 该组的累计复合收益 | 反映总体表现 |
| **单调性** | 收益 ≥ 组2 ≥ ... ≥ 组5？ | 是 = 小市值溢价存在 |
| **超额收益** | 组1收益 - 组5收益 | 小市值相对最大市值的优势 |

### 例子

```
第1组（最小）: 平均收益5.2%, 累计收益65%, 29只股票
第2组:        平均收益3.8%, 累计收益48%, 29只股票
第3组:        平均收益2.1%, 累计收益26%, 29只股票
第4组:        平均收益1.5%, 累计收益18%, 29只股票
第5组（最大）: 平均收益0.8%, 累计收益10%, 29只股票

单调性检验: ✓ 通过（5.2% > 3.8% > 2.1% > 1.5% > 0.8%）
第1组超额收益: 5.2% - 0.8% = 4.4%
```

**解读：** 小市值组（第1组）显著跑赢大市值组（第5组），超额收益 4.4%，说明策略的小市值选股逻辑有效。

## 3. 因子暴露分析

### 三大维度

#### 3.1 行业权重对比

比较策略持仓和全市场等权基准的行业配置差异：

```
策略行业权重：
  制造业(C34): 25%
  金融业(J66): 15%
  ...

基准行业权重：
  制造业(C34): 10%
  金融业(J66): 10%
  ...

超配权重：
  制造业: 25% - 10% = +15%  (超配)
  金融业: 15% - 10% = +5%   (超配)
```

**解读：** 策略相对基准超配制造业 15%，说明策略集中在小市值密集的行业（制造业）。

#### 3.2 市值暴露

比较策略和基准的平均市值：

```
策略平均市值:   8.5亿元
基准平均市值:   50亿元
相对比例:       8.5 / 50 = 17%
```

**解读：** 策略的平均持股市值是基准的 17%，显示强烈的小市值暴露（这是预期的）。

#### 3.3 流动性暴露

比较策略和基准的平均 ADV20：

```
策略平均ADV20:  2500万元
基准平均ADV20:  8000万元
相对比例:       2500 / 8000 = 31%
```

**解读：** 策略持仓的平均流动性低于基准，风险是流动性约束下的执行成本更高。

## 4. 行业中性 Alpha 分解

### 公式

```
总超额收益 = 行业配置贡献 + 选股 Alpha

其中：
行业配置贡献 = Σ(行业权重 × 行业超额收益)
选股 Alpha = 总超额收益 - 行业配置贡献
Alpha比率 = 选股Alpha / 总超额收益
```

### 例子

假设某回测期间：
- 策略总收益：15%
- 基准总收益：10%
- **总超额收益：5%**

行业贡献计算（假设只有一个行业）：
- 策略 100% 配置在制造业
- 基准 50% 配置在制造业
- 制造业超额收益：12% - 10% = 2%
- **行业贡献 = 100% × 2% = 2%**

Alpha 分解：
- **选股 Alpha = 5% - 2% = 3%**
- **Alpha 比率 = 3% / 5% = 60%**

**解读：** 策略的 5% 超额收益中，2% 来自行业配置的优势（正好持有了表现好的制造业），3% 来自真正的选股能力。Alpha 比率 60% 说明选股贡献占比较高。

```bash
curl -X POST http://127.0.0.1:8001/api/backtest \
  -H "Content-Type: application/json" \
  -d '{
    "start_date": "2023-01-01",
    "end_date": "2024-12-31",
    "initial_cash": 1000000,
    "target_stocks": 30,
    "target_budget": 0.9,
```

```bash

  -H "Content-Type: application/json" \
```

- **JSON 报告**：`outputs/{experiment_id}/factor_analysis.json`
- **HTML 报告**：`outputs/{experiment_id}/factor_report.html`（可在浏览器中打开）

## 常见问题

### Q1: IC 计算时为什么有些样本数较少？

**A:** 如果某些股票在回测期间停牌、退市或缺失数据，会被自动剔除。样本数反映了有效的数据。

### Q2: 分组时如果候选少于 5 只怎么办？

**A:** 系统会按实际数量分组。例如如果只有 3 只候选，则分成 3 组。

### Q3: 基准的行业权重如何计算？

**A:** 基准采用全市场等权重，即每只股票权重 = 1 / 全市场股票总数。

### Q4: 为什么 Alpha ratio 可能为负？

**A:** 当行业配置贡献超过总超额收益时，选股 Alpha 为负，说明选股拖累了整体表现。

### Q5: IC 的 p-value 为 1.0 表示什么？

**A:** 通常表示样本太少（< 3只）或无法计算秩相关。这时 IC 被设置为 0.0。

## 技术细节

### 数据处理

- **缺失数据**：自动剔除缺失收益或市值数据的股票
- **停牌股票**：不参与 IC 和分组计算
- **退市股票**：同上
- **极端值**：秩相关对异常值有天然抗性，无需特殊处理

### 精度

- 所有金融计算精确到分（0.01元）
- IC 和收益率精确到 4 位小数
- 权重精确到 4 位小数

### 性能

- 完整因子分析通常在 30-60 秒内完成（取决于数据量）
- HTML 报告生成 < 1 秒
